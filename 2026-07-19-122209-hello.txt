  ★ Insight ─────────────────────────────────────

  Key architectural decisions for a multi-format editor:

  1. PySide6 over PyQt6: LGPL license means you can distribute proprietary
  software without GPL restrictions - critical for desktop apps you might want
  to share.
  2. Isolated Python execution: For pandas tables, we'll need to execute Python
  code in a sandboxed environment (using RestrictedPython or similar) to prevent
  arbitrary code execution from markdown files.
  3. Format-agnostic architecture: Using a handler pattern where each format
  (markdown, json, yaml) has its own handler class makes the code maintainable
  and extensible.
  ─────────────────────────────────────────────────

  ---
  My Recommendations

  Based on your preferences and the design analysis, here's my recommended
  approach:

  1. GUI Framework: PySide6

  - Cross-platform with LGPL license
  - Excellent QSplitter for the toggleable split view
  - Built-in QTabWidget for tabbed interface
  - QGraphicsView can render pandas tables as interactive grids

  2. Architecture Pattern

  MainWindow
  ├── QTabWidget (tabs on either side of split)
  ├── QSplitter (toggleable split between editor/preview)
  └── QTabBar (movable tabs)

  3. Pandas Table Implementation

  For interactive editing, I recommend:
  - Execution sandbox: Use RestrictedPython or a subprocess with limited imports
  - Table widget: QTableView with custom model for DataFrame data
  - Edit-in-place: Double-click opens cell editor, changes propagate back to
  source markdown

  4. Syntax Highlighting

  Create a unified SyntaxHighlighter class that:
  - Detects file type automatically
  - Applies appropriate highlighting rules
  - Supports themes (light/dark)

  5. Distribution

  For cross-platform builds, I recommend PyInstaller with:
  - Onefile executable for easy distribution
  - --windowed flag for no console window

  ★ Insight ─────────────────────────────────────

  Key implementation decisions in this MVP:

  1. Handler pattern via DocumentTab: Each file is wrapped in a DocumentTab that
  tracks format, content, and file path. The editor/preview widgets read from
  this model, keeping UI separate from data.
  2. QSyntaxHighlighter subclasses: We subclass QSyntaxHighlighter for each
  format (Markdown/JSON/YAML). The highlighter's highlightBlock() is called
  per-line as you type—this is why syntax highlighting stays smooth even on
  large files.
  3. Pandas execution sandbox: PandasTableProcessor.execute_pandas_code() uses
  exec() with a restricted namespace containing only pandas, numpy, and pd—no
  open, import of arbitrary modules, or filesystem access. This prevents
  arbitrary code execution from untrusted .md files. You'd tighten this further
  (e.g., RestrictedPython) before shipping.
